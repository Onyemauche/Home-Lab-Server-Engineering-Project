
# Server Hardware Selection and Engineering

## 1. Introduction

### 1.1 Purpose

This document explains how to select, evaluate, assemble, and prepare the physical hardware required for the Home Lab Server Engineering project.

A server is not defined by its physical appearance. It is defined by the computing resources it provides and the services it delivers to other systems.

A desktop computer, workstation, mini PC, or dedicated server can all perform server workloads when appropriately configured.

The objective is to select hardware that can reliably support the intended workloads without unnecessary expenditure.

### 1.2 Hardware Engineering Objectives

This stage aims to:

- Understand the components of a physical server.
- Understand how the components interact.
- Compare consumer and server-oriented hardware.
- Evaluate processor performance and compatibility.
- Select appropriate memory capacity.
- Understand storage technologies.
- Evaluate motherboard expansion capabilities.
- Understand network interfaces.
- Plan power delivery and cooling.
- Consider electricity consumption.
- Evaluate future upgrade possibilities.
- Document the actual hardware configuration.

### 1.3 Initial Workloads

The selected hardware should support:

1. Ubuntu Server LTS.
2. OpenSSH remote administration.
3. UFW firewall.
4. Nginx web server.
5. PostgreSQL database.
6. Go backend applications.
7. Docker containers.
8. Basic system monitoring.
9. Backup operations.

Virtual machines and more demanding workloads may be introduced later.

# 2. Understanding Server Hardware

A physical server consists of several interconnected hardware components.

| Component | Primary responsibility |
|---|---|
| CPU | Executes instructions and processes workloads |
| RAM | Holds active programs and working data |
| Motherboard | Connects and coordinates hardware components |
| Storage | Retains the operating system, applications and data |
| NIC | Provides network connectivity |
| PSU | Supplies electrical power |
| Cooling | Removes heat generated by components |
| Case | Houses and protects the hardware |
| UPS | Provides temporary backup power |

A server's overall capabilities depend on how these components work together.

For example, installing a powerful CPU does not automatically create a powerful server if the machine has insufficient RAM, slow storage, poor cooling, or inadequate networking.

# 3. Central Processing Unit (CPU)

## 3.1 What Is a CPU?

The Central Processing Unit is the primary general-purpose processor in a computer.

It executes instructions, performs calculations, processes application logic, and coordinates many computing operations.

In a server, the CPU may handle:

- Web requests.
- Database queries.
- Backend application logic.
- Encryption and decryption.
- File processing.
- Compression.
- Virtual machines.
- Container workloads.
- System processes.

The processor influences how many tasks the server can handle and how quickly it can execute them.

## 3.2 CPU Cores

A CPU core is an individual processing unit within a processor.

A processor with four physical cores can execute work across four cores concurrently, subject to the operating system and workload.

More cores are useful when a server runs multiple applications simultaneously.

Example:

| Processor configuration | General capability |
|---|---|
| 2 cores | Basic server workloads |
| 4 cores | Small server with several services |
| 6 cores | More room for simultaneous workloads |
| 8 cores | More flexibility for virtualization and multitasking |
| 12+ cores | More demanding workloads and multiple virtual machines |

These are general planning categories, not performance guarantees. Processor generation, architecture, clock speed and workload also matter.

## 3.3 CPU Threads

A thread represents a sequence of instructions that can be scheduled for execution.

Modern processors may support simultaneous multithreading.

For example:

A processor with four physical cores and eight logical processors can expose eight logical CPUs to the operating system.

Logical processors are not equivalent to physical cores. Two threads sharing one physical core still share some execution resources.

## 3.4 Clock Speed

Clock speed describes the operating frequency of a processor.

It is commonly measured in gigahertz (GHz).

For example:

- 2.0 GHz
- 2.5 GHz
- 3.0 GHz
- 4.0 GHz

Higher clock speed can improve performance in certain workloads, but GHz alone is not a reliable way to compare different processor architectures.

Consider:

- Processor generation.
- Instructions per clock.
- Core count.
- Cache.
- Power limits.
- Thermal limits.
- Workload characteristics.

## 3.5 CPU Cache

Cache is high-speed memory located within or close to the processor.

It stores frequently accessed data and instructions to reduce the time required to retrieve them from slower memory.

Common cache levels:

- L1 cache: Small and extremely fast.
- L2 cache: Larger than L1, generally slower.
- L3 cache: Often shared among multiple cores.

Cache architecture can influence application performance, especially in workloads involving repeated data access.

## 3.6 CPU Virtualization Support

Virtualization allows one physical machine to host multiple virtual machines.

Common processor technologies include:

- Intel VT-x.
- Intel VT-d.
- AMD-V.
- AMD-Vi.

These technologies support hardware-assisted virtualization and device virtualization features.

Before selecting a processor for future Proxmox or KVM use, verify that the processor and motherboard support the required virtualization features.

The features must also be enabled in BIOS/UEFI when required.

## 3.7 Processor Families

Two major processor manufacturers are:

**Intel**
- Intel Core processors.
- Intel Core Ultra processors.
- Intel Xeon processors.

**AMD**
- AMD Ryzen processors.
- AMD Ryzen PRO processors.
- AMD EPYC processors.

Consumer processors can be suitable for small home servers.

Workstation and server processors may offer additional capabilities, depending on the platform:

- Greater memory capacity.
- ECC memory support.
- More PCIe connectivity.
- Additional processor cores.
- Platform management features.
- More expansion possibilities.

The exact capabilities depend on the processor and motherboard combination.

## 3.8 CPU Selection for This Project

Suggested starting characteristics:

| Attribute | Preferred target |
|---|---|
| Architecture | 64-bit x86-64 |
| Physical cores | 4 or more |
| Virtualization | Hardware virtualization support |
| Integrated graphics | Useful for initial setup |
| Power consumption | Reasonable for extended operation |
| Compatibility | Supported by motherboard and Ubuntu |

A modern 4-core processor is sufficient for the initial stages.

A 6-core or 8-core processor provides more room for expansion, particularly if several containers or virtual machines are introduced.

## 3.9 CPU Compatibility Checklist

Before purchasing a processor, confirm:

- [ ] Motherboard socket matches the CPU.
- [ ] Motherboard BIOS supports the CPU.
- [ ] Chipset supports the processor.
- [ ] CPU power requirements are supported.
- [ ] Compatible CPU cooling is available.
- [ ] Virtualization requirements are satisfied.
- [ ] Integrated graphics requirements are understood.
- [ ] Memory compatibility has been checked.

# 4. Random Access Memory (RAM)

## 4.1 What Is RAM?

Random Access Memory is temporary working memory used by the operating system and running applications.

When an application runs, its active instructions and data are loaded into memory.

RAM is volatile: its contents are generally lost when electrical power is removed.

A server uses RAM for:

- Operating system processes.
- Application execution.
- Database operations.
- Filesystem caching.
- Web server processes.
- Container workloads.
- Virtual machines.

Insufficient RAM can result in performance degradation and excessive use of swap space.

## 4.2 RAM Capacity

The amount of RAM determines how much active data and how many workloads can be held in memory.

Suggested capacities for this project:

| RAM | Intended use |
|---|---|
| 8 GB | Basic Linux server and lightweight services |
| 16 GB | Recommended starting configuration |
| 32 GB | Multiple applications and several small virtual machines |
| 64 GB | Larger virtualization experiments |
| 128 GB+ | More demanding workloads, subject to platform support |

These are planning estimates. Actual requirements depend on applications, databases, VM allocation and workload intensity.

## 4.3 DDR Memory Generations

DDR stands for Double Data Rate.

Common desktop memory generations include:

- DDR3.
- DDR4.
- DDR5.

Different generations have different electrical and physical specifications.

A DDR4 memory module cannot simply be inserted into a DDR5 motherboard.

Memory selection must match the motherboard and processor specifications.

## 4.4 Memory Channels

Memory channels describe the communication paths between the memory controller and RAM.

Common configurations include:

- Single-channel.
- Dual-channel.
- Quad-channel.
- Eight-channel on certain server platforms.

Installing memory in the correct motherboard slots can enable the intended channel configuration.

Consult the motherboard manual for recommended DIMM population.

## 4.5 ECC Memory

ECC means Error-Correcting Code.

ECC memory can detect and correct certain memory errors.

It is particularly relevant in systems where data integrity and continuous operation are important.

Potential advantages:

- Detection of certain memory errors.
- Correction of certain single-bit errors.
- Additional protection against memory-related data corruption.

ECC support depends on the complete platform.

Check:

1. CPU support.
2. Motherboard support.
3. Memory module compatibility.
4. BIOS/UEFI support.
5. Whether ECC operation is actually enabled.

Installing an ECC memory module does not automatically mean the system operates with ECC functionality.

## 4.6 Registered and Unbuffered Memory

Two important memory categories are:

**UDIMM — Unbuffered DIMM**

Commonly used in desktop systems and some smaller servers.

**RDIMM — Registered DIMM**

Uses a register between the memory controller and memory chips to support larger memory configurations on compatible platforms.

RDIMM and UDIMM modules are generally not interchangeable.

Do not mix them unless the platform documentation explicitly supports the configuration.

## 4.7 RAM Selection for This Project

Initial recommendation:

- 16 GB minimum target.
- 32 GB preferred if virtualization is an important near-term objective.
- Dual-channel configuration where supported.
- Compatible memory speed and generation.
- ECC where supported and affordable.

The actual system memory configuration must be recorded after hardware inspection.

# 5. Storage Systems

## 5.1 What Is Storage?

Storage retains information when the server is powered off.

It holds:

- Operating system files.
- Applications.
- Databases.
- Website content.
- Logs.
- Backups.
- Configuration files.
- User data.

Storage performance and reliability affect server responsiveness and data protection.

## 5.2 Hard Disk Drive (HDD)

An HDD stores data on rotating magnetic platters.

Advantages:

- Often lower cost per gigabyte.
- Suitable for bulk storage.
- Available in large capacities.

Disadvantages:

- Mechanical moving components.
- Slower random access compared with SSDs.
- More sensitive to physical shock.
- Can produce additional noise.

Potential uses:

- File storage.
- Backup destinations.
- Large datasets.
- Media storage.

## 5.3 Solid State Drive (SSD)

An SSD stores data using flash memory.

Advantages:

- Faster access than traditional HDDs.
- No moving mechanical parts.
- Lower latency.
- Generally quieter.
- Useful for operating systems and databases.

Disadvantages:

- Cost per gigabyte can be higher.
- Flash memory has finite write endurance.
- Performance and endurance vary by model.

## 5.4 SATA SSD

SATA SSDs connect through the SATA interface.

They are common in desktop and business computers.

Advantages:

- Broad compatibility.
- Useful for operating systems.
- Suitable for general application hosting.

## 5.5 NVMe SSD

NVMe is a storage protocol designed for non-volatile memory devices, commonly using PCIe connectivity.

NVMe SSDs generally provide higher throughput and lower latency than SATA SSDs.

They are commonly installed in M.2 form factors.

Important distinction:

M.2 is a physical form factor. NVMe is a storage protocol.

Not every M.2 SSD uses NVMe. Some M.2 devices use SATA.

Check the motherboard's M.2 slot specifications before purchasing.

## 5.6 Storage Comparison

| Feature | HDD | SATA SSD | NVMe SSD |
|---|---|---|---|
| Moving parts | Yes | No | No |
| Interface | SATA or other HDD interfaces | SATA | PCIe |
| Random access | Relatively slow | Fast | Generally faster |
| Bulk storage cost | Often lower | Higher | Often higher |
| Common use | Storage and backups | General server storage | OS and high-performance storage |

## 5.7 Storage Capacity Planning

Suggested starting configuration:

| Storage | Purpose |
|---|---|
| 500 GB SSD | Operating system and initial applications |
| Additional HDD or SSD | Optional data and backup storage |
| External storage | Separate backup destination |

A single SSD is sufficient for the initial learning server.

Additional storage should be introduced when actual capacity or backup requirements justify it.

## 5.8 Storage Endurance

SSD endurance is often represented using TBW.

TBW means Terabytes Written.

It describes the manufacturer's rated write endurance under specified conditions.

Consider:

- Total expected write activity.
- Drive health.
- Temperature.
- Available capacity.
- Manufacturer specifications.
- Warranty conditions.

Database workloads can generate significant write activity, so drive selection should consider endurance as well as speed.

## 5.9 Understanding RAID

RAID means Redundant Array of Independent Disks.

RAID combines multiple storage devices into a logical storage arrangement.

Common levels:

**RAID 0**
- Data is striped across drives.
- Can improve throughput.
- Provides no redundancy.
- Failure of one drive can destroy the array's data.

**RAID 1**
- Data is mirrored.
- Provides redundancy against one drive failing in a two-drive mirror.
- Usable capacity is approximately that of one drive.

**RAID 5**
- Uses striping and distributed parity.
- Requires at least three drives.
- Can tolerate one drive failure.
- Has rebuild and performance considerations.

**RAID 10**
- Combines mirroring and striping.
- Requires at least four drives.
- Offers performance and redundancy benefits.

RAID is not a backup.

It does not protect against accidental deletion, malware, theft, fire, or every form of data corruption.

## 5.10 Storage Selection for This Project

Initial recommendation:

- 500 GB SSD.
- NVMe where compatible and affordable.
- SATA SSD where better compatibility or cost makes sense.
- Separate backup destination for important files.

Avoid creating complicated RAID configurations during the first installation.

Learn storage management first, then introduce redundancy in a controlled stage.

# 6. Motherboard

## 6.1 What Is a Motherboard?

The motherboard is the main circuit board that connects the CPU, RAM, storage, expansion cards, power supply and peripheral devices.

It determines many hardware compatibility and expansion limitations.

## 6.2 Important Motherboard Components

| Component | Function |
|---|---|
| CPU socket | Holds the processor |
| DIMM slots | Hold RAM modules |
| Chipset | Provides platform connectivity and features |
| PCIe slots | Connect expansion cards |
| SATA connectors | Connect SATA storage |
| M.2 slots | Support compatible SSDs and other devices |
| Ethernet controller | Provides wired network connectivity |
| BIOS/UEFI | Initializes hardware and provides firmware settings |
| Power connectors | Deliver power to the motherboard and CPU |

## 6.3 Motherboard Form Factors

Common form factors include:

- ATX.
- Micro-ATX.
- Mini-ITX.
- E-ATX.

Form factor influences physical dimensions, case compatibility, expansion slots and available connectors.

## 6.4 PCI Express

PCI Express (PCIe) is an interface for connecting expansion devices.

Examples include:

- Network interface cards.
- Storage controllers.
- Graphics cards.
- Additional storage adapters.

Common physical slot configurations include:

- PCIe x1.
- PCIe x4.
- PCIe x8.
- PCIe x16.

The physical slot size and actual electrical lane configuration are not always identical.

Check motherboard specifications.

## 6.5 Motherboard Selection Criteria

Evaluate:

- CPU socket.
- Processor compatibility.
- Supported RAM type.
- Maximum RAM capacity.
- ECC support.
- Number of memory slots.
- M.2 connectivity.
- SATA connectivity.
- PCIe expansion.
- Integrated networking.
- BIOS support.
- Power delivery.
- Physical dimensions.

A motherboard should be selected as part of a compatible platform rather than independently.

# 7. Network Interface Hardware

## 7.1 What Is a Network Interface Controller?

A Network Interface Controller (NIC) allows a server to communicate with other devices over a network.

A wired NIC connects through Ethernet.

It provides the physical and data-link interface used to transmit and receive network traffic.

## 7.2 Ethernet Speeds

Common Ethernet speeds include:

| Speed | Typical application |
|---|---|
| 100 Mbps | Older or limited network connections |
| 1 Gbps | Standard home server connectivity |
| 2.5 Gbps | Faster local network connectivity |
| 10 Gbps | High-throughput storage and network workloads |
| 25 Gbps+ | More demanding enterprise environments |

The speed of the complete network connection depends on the server NIC, switch, router, cable and client device.

A 10 Gbps NIC connected to a 1 Gbps switch will not produce a 10 Gbps end-to-end link.

## 7.3 Network Cabling

Common Ethernet cable categories:

- Cat5e.
- Cat6.
- Cat6a.

Cable selection should match the intended speed, distance and installation environment.

For this initial project, a suitable Cat5e or Cat6 cable is generally sufficient for a Gigabit Ethernet connection.

## 7.4 Network Interface Selection

Preferred initial characteristics:

- Gigabit Ethernet.
- Stable Linux driver support.
- Standard Ethernet connectivity.
- Reliable link negotiation.
- Optional expansion through PCIe.

A separate network card is unnecessary if the motherboard already provides a suitable Ethernet controller.

# 8. Power Supply Unit (PSU)

## 8.1 What Is a PSU?

The Power Supply Unit converts incoming electrical power into the regulated voltages required by computer components.

It powers:

- Motherboard.
- CPU.
- Storage devices.
- Cooling fans.
- Expansion cards.

## 8.2 PSU Selection

Evaluate:

- Required wattage.
- PSU quality.
- Efficiency rating.
- Available connectors.
- Protection features.
- Cooling.
- Physical dimensions.
- Manufacturer specifications.

Do not select a PSU based only on its advertised wattage.

A higher wattage rating does not automatically mean better quality.

## 8.3 Efficiency

PSU efficiency describes how effectively incoming power is converted into usable output power.

The 80 PLUS certification program provides efficiency classifications for participating power supplies.

Efficiency can affect electricity costs over extended operation.

Actual power consumption depends on the entire system and workload.

## 8.4 Power Consumption

A server running continuously consumes electricity even when workload activity is low.

Factors include:

- CPU power usage.
- Storage devices.
- Motherboard.
- Cooling fans.
- Expansion cards.
- Power supply efficiency.

A lower-power system can reduce long-term operating costs.

Measure actual consumption where possible using a suitable power meter.

### Power Cost Estimation

Use:

Energy consumed (kWh) = Average power (W) × Operating hours ÷ 1000

Estimated monthly energy:

Monthly kWh = Average power (W) × 24 × 30 ÷ 1000

Example:

For a server averaging 40 watts:

40 × 24 × 30 ÷ 1000 = 28.8 kWh per month.

This is an illustrative estimate, not a measurement of the actual server.

Monthly electricity cost:

Monthly cost = Monthly kWh × Electricity tariff per kWh.

Record the applicable tariff and actual measured consumption separately.

# 9. Cooling and Thermal Management

## 9.1 Why Cooling Matters

Electronic components generate heat during operation.

Excessive temperatures can cause:

- Thermal throttling.
- Reduced performance.
- System instability.
- Unexpected shutdowns.
- Reduced component lifespan.

Proper cooling is essential for extended server operation.

## 9.2 Cooling Components

Typical cooling components include:

- CPU cooler.
- Case fans.
- Heatsinks.
- Thermal interface material.
- Air intake and exhaust openings.

## 9.3 Airflow

A common airflow arrangement is:

1. Cool air enters through front or side intake fans.
2. Air moves through the case.
3. Heat is removed from the CPU and other components.
4. Warm air exits through rear or top exhaust fans.

The correct configuration depends on the case design.

Avoid blocking ventilation openings.

## 9.4 Thermal Monitoring

After installation, monitor:

- CPU temperature.
- CPU utilization.
- Fan operation.
- Storage temperature where supported.
- Thermal throttling indicators.

Temperature limits vary by component.

Consult the manufacturer's specifications rather than assuming one universal safe temperature.

# 10. Uninterruptible Power Supply (UPS)

## 10.1 What Is a UPS?

An Uninterruptible Power Supply provides temporary backup power when the primary electrical supply is interrupted.

It can help a server remain operational briefly or shut down safely.

## 10.2 Why a UPS Is Useful

Power interruptions can cause:

- Unexpected shutdowns.
- Interrupted database writes.
- Filesystem inconsistencies.
- Service interruptions.
- Loss of unsaved data.

A UPS provides an opportunity to handle these events more safely.

## 10.3 UPS Selection

Evaluate:

- VA rating.
- Watt rating.
- Battery capacity.
- Expected runtime.
- Battery replacement availability.
- Supported monitoring interface.
- USB or network connectivity.
- Surge protection.
- Connected equipment.

VA and watts are different measurements.

The UPS must support the actual electrical load, not just the advertised VA number.

## 10.4 UPS Runtime Planning

Runtime depends on:

- Actual connected load.
- Battery capacity.
- Battery condition.
- UPS efficiency.
- Battery discharge characteristics.

Do not assume that a particular VA rating guarantees a specific runtime.

A UPS should be tested periodically.

# 11. Server Form Factors

There are several ways to build the physical server.

## 11.1 Refurbished Business Desktop

A refurbished business desktop is often a practical starting point.

Advantages:

- Lower initial cost.
- Existing case and motherboard.
- Existing power supply.
- Relatively easy installation.
- Often available with upgradeable RAM and storage.

Disadvantages:

- Older processors.
- Limited expansion.
- Proprietary components in some models.
- Possible power supply limitations.
- Unknown previous operating conditions.

Suitable for:

- Ubuntu Server.
- Nginx.
- PostgreSQL.
- Backend development.
- Lightweight Docker workloads.

## 11.2 Mini PC

A mini PC is a compact computer designed to provide desktop computing in a small enclosure.

Advantages:

- Small physical footprint.
- Low power consumption in many models.
- Quiet operation in suitable designs.
- Convenient installation.
- Suitable for lightweight home server workloads.

Disadvantages:

- Limited expansion.
- Memory may be soldered.
- Limited storage capacity.
- Thermal limitations on some models.
- Fewer PCIe expansion options.

Suitable for:

- Lightweight server applications.
- Web hosting.
- Small databases.
- Network services.
- Development environments.

## 11.3 Custom-Built Tower

A custom tower is assembled from individually selected components.

Advantages:

- Component selection.
- Greater upgrade flexibility.
- More expansion possibilities.
- Choice of storage configuration.
- Better control over cooling and power.

Disadvantages:

- Higher initial cost in some configurations.
- Compatibility must be verified.
- Requires assembly.
- Requires more hardware troubleshooting.

Suitable for:

- Multiple services.
- Larger databases.
- Virtualization.
- Multiple storage devices.
- More demanding home lab workloads.

## 11.4 Form Factor Comparison

| Factor | Refurbished desktop | Mini PC | Custom tower |
|---|---|---|---|

# 14. Hardware Assembly Procedure

This section applies when building a custom system.

For a preassembled desktop or mini PC, skip the assembly steps that do not apply.

## 14.1 Preparation

Required items may include:

- Compatible computer components.
- Suitable screwdriver.
- Anti-static precautions.
- Thermal interface material if required.
- Monitor.
- Keyboard.
- Power cable.
- Ethernet cable.

Before assembly:

1. Confirm all components are compatible.
2. Review the motherboard manual.
3. Work on a clean, stable surface.
4. Disconnect the PSU from electrical power.
5. Take precautions against electrostatic discharge.

## 14.2 Assembly Sequence

1. Inspect the motherboard and components.
2. Install the CPU according to the socket instructions.
3. Install the CPU cooler.
4. Install RAM in the recommended slots.
5. Install the M.2 SSD if applicable.
6. Install the motherboard in the case.
7. Install the power supply.
8. Connect motherboard power.
9. Connect CPU power.
10. Connect storage cables where required.
11. Connect case fans.
12. Connect the case front-panel connectors.
13. Check all connections.
14. Inspect for loose screws or cables.
15. Connect the monitor, keyboard and power cable.
16. Power on the system.
17. Confirm successful POST and BIOS/UEFI access.

POST means Power-On Self-Test.

It is the initial hardware checking process performed when a computer starts.

## 14.3 First Boot Validation

Confirm:

- CPU is recognized.
- RAM capacity is correct.
- Storage is detected.
- Cooling is working.
- Fans are operating.
- No unexpected hardware errors are displayed.

Do not proceed to operating system installation until basic hardware functionality is confirmed.

# 15. Hardware Failure Considerations

Possible hardware problems include:

| Component | Potential failure | Possible symptoms |
|---|---|---|
| CPU | Overheating or failure | Instability, shutdowns |
| RAM | Memory errors | Crashes, failed boot |
| SSD | Media or controller failure | Storage errors, inaccessible data |
| HDD | Mechanical failure | Noise, read/write errors |
| PSU | Power delivery failure | Unexpected shutdowns |
| Motherboard | Component or circuit failure | Boot or hardware detection issues |
| NIC | Interface failure | Network connectivity problems |
| Cooling fan | Fan failure | Rising component temperatures |

Troubleshooting should begin with observation and diagnosis.

Do not assume that a particular symptom always identifies a specific failed component.

# 20. Conclusion

Hardware selection is the foundation of a reliable server environment.

The processor determines processing capabilities, RAM supports active workloads, storage retains data, networking enables communication, and power and cooling support continuous operation.

The best hardware configuration is not necessarily the most expensive or powerful.

It is the configuration that satisfies the intended workloads, remains compatible, operates reliably, and provides sufficient room for future development.

**Engineering principle: Understand the workload first. Select compatible hardware second. Verify the complete system before deployment.**
